1. **容器重建数据零丢失**：hive-server 因 PID 残留无法启动，用 compose --force-recreate 重建后，命名卷（hive-warehouse）持久化生效，dwd_order 直接查出 15000 行——第 4 周的数据持久化加固经实测有效；
2. **统计信息核对教训**：核对过程中曾出现 COUNT(*) 与 GROUP BY 求和不一致的"假象"，逐层排查（物理文件→表统计信息→原始数据 dump）后确认为核对脚本表头过滤与预期值口径问题，非数据问题；原始 dump 逐行分组统计与 SQL 聚合完全一致（997 行：201/379/309/108），该排查过程本身验证了数仓数据的可靠性；
3. **一键复现能力**：全部脚本（sql/replay_all.sh + superset_setup.py + superset_charts.py + load_mysql.py）入库，任意时刻可从零重建整个系统。
